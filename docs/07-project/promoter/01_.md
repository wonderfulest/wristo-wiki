# 一、总体目标

支持这种场景：

> 用户 **不点推广链接**，只是在下单页 / 支付页 **手动输入推广口令（折扣码）**，系统仍能识别推广员并分佣。

例如：

```
下单时输入：WRISTO88
```

系统自动：

- 给用户优惠
- 识别推广员
- 记录归因
- 计算佣金
- 进入结算体系

------

# 二、整体架构设计

```
推广员 → 获取专属口令 → 分享给用户
                         ↓
用户下单 → 输入口令 → 校验 → 绑定推广员
                         ↓
                   创建分佣记录
                         ↓
                     结算系统
```

口令体系 ≠ 短链体系
 👉 是 **独立归因通道**

| 归因方式    | 用途      |
| ----------- | --------- |
| short_link  | 社媒/广告 |
| coupon_code | 私域/口令 |

统一进分佣系统。

------

# 三、核心新增表设计（口令体系）

## 1️⃣ 推广口令表（核心）

```
CREATE TABLE promoter_coupon (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,

  coupon_code VARCHAR(32) NOT NULL COMMENT '推广口令/折扣码',

  promoter_id BIGINT NOT NULL COMMENT '推广员ID',
  campaign_id BIGINT DEFAULT NULL COMMENT '关联活动',

  discount_type ENUM('PERCENT','FIXED') NOT NULL,
  discount_value DECIMAL(10,2) NOT NULL,
	
	paddle_discount_id ,
  commission_rate DECIMAL(5,2) NOT NULL COMMENT '分佣比例(%)',

  max_use INT DEFAULT NULL COMMENT '最大使用次数',
  used_count INT DEFAULT 0,

  status ENUM('ACTIVE','DISABLED','EXPIRED') DEFAULT 'ACTIVE',

  expire_at DATETIME DEFAULT NULL,

  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,

  UNIQUE KEY uk_coupon (coupon_code),
  KEY idx_promoter (promoter_id)
) ENGINE=InnoDB COMMENT='推广口令表';
```

### 作用

| 字段            | 作用           |
| --------------- | -------------- |
| coupon_code     | 用户输入的口令 |
| promoter_id     | 归属推广员     |
| commission_rate | 分佣比例       |
| max_use         | 控制刷单       |
| expire_at       | 失效控制       |

------

## 2️⃣ 订单归因表（支持口令+短链）

统一入口。

```
CREATE TABLE promoter_order_attribution (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,

  order_id BIGINT NOT NULL,

  user_id BIGINT NOT NULL,

  promoter_id BIGINT DEFAULT NULL,

  source_type ENUM('SHORT_LINK','COUPON','MANUAL') NOT NULL,

  source_code VARCHAR(64) DEFAULT NULL COMMENT '短链code或口令',

  coupon_id BIGINT DEFAULT NULL,

  order_amount DECIMAL(12,2) NOT NULL,

  commission_amount DECIMAL(12,2) NOT NULL,

  status ENUM('PENDING','CONFIRMED','CANCELLED','SETTLED')
    DEFAULT 'PENDING',

  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,

  UNIQUE KEY uk_order (order_id),
  KEY idx_promoter (promoter_id),
  KEY idx_source (source_type,source_code)
) ENGINE=InnoDB COMMENT='订单推广归因表';
```

### 作用

统一存：

- 来自短链
- 来自口令
- 来自人工

------

## 3️⃣ 分佣流水表

```
CREATE TABLE promoter_commission_log (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,

  promoter_id BIGINT NOT NULL,

  order_id BIGINT NOT NULL,

  attribution_id BIGINT NOT NULL,

  base_amount DECIMAL(12,2) NOT NULL COMMENT '订单金额',

  rate DECIMAL(5,2) NOT NULL,

  commission_amount DECIMAL(12,2) NOT NULL,

  status ENUM('INIT','LOCKED','PAID','REFUNDED')
    DEFAULT 'INIT',

  settle_batch_id BIGINT DEFAULT NULL,

  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,

  KEY idx_promoter (promoter_id),
  KEY idx_order (order_id)
) ENGINE=InnoDB COMMENT='推广分佣流水';
```

------

## 4️⃣ 结算批次表

```
CREATE TABLE promoter_settlement_batch (
  id BIGINT UNSIGNED AUTO_INCREMENT PRIMARY KEY,

  batch_no VARCHAR(64) NOT NULL,

  period_start DATE NOT NULL,
  period_end DATE NOT NULL,

  total_amount DECIMAL(14,2) NOT NULL,

  status ENUM('INIT','PROCESSING','DONE','FAILED')
    DEFAULT 'INIT',

  created_at DATETIME DEFAULT CURRENT_TIMESTAMP,

  UNIQUE KEY uk_batch (batch_no)
) ENGINE=InnoDB COMMENT='推广结算批次';
```

# 四、下单时的业务流程（口令模式）

## ① 用户输入口令

前端：

```
输入框：请输入优惠码
```

提交：

```
couponCode=WRISTO88
```

------

## ② 校验口令

服务端：

```
SELECT *
FROM promoter_coupon
WHERE coupon_code = ?
  AND status='ACTIVE'
  AND (expire_at IS NULL OR expire_at > NOW())
```

校验：

- 是否存在
- 是否过期
- 是否超限

------

## ③ 计算优惠 + 佣金

示例：

```
订单金额：100
折扣：10%
佣金：20%
```

计算：

```
实付 = 90
佣金 = 100 * 20% = 20
```

------

## ④ 创建归因记录

```
INSERT promoter_order_attribution
source_type = COUPON
source_code = WRISTO88
promoter_id = xxx
```

------

## ⑤ 创建分佣流水

```
INSERT promoter_commission_log
```

状态：INIT → LOCKED

------

## ⑥ 订单确认后锁定佣金

订单完成：

```
PENDING → CONFIRMED
INIT → LOCKED
```

退款则回滚。

# 十、总结一句话方案

你的最佳结构是：

> ✅ 短链负责公域获客
> ✅ 口令负责私域转化
> ✅ attribution 统一归因
> ✅ commission 独立结算

这是目前电商 + SaaS 推广最成熟模式。
