# 总体思路（改造后）

> **原则**：
>
> - 不用 View
> - 所有“中间结论”**落表**
> - 任何一步都可以 `SELECT *` 看数据
> - 可以随时重跑、增量跑

流程变成：

```
search_record
   ↓（归一化）
search_record.normalized_keyword
   ↓（意图完成态判定 → 落表）
final_search_keyword
   ↓（聚合 → 落表）
product_keyword_candidate
```

------

# Step 1️⃣ normalized_keyword（这一步你可以保持不变）

这一段你现在的设计 **非常好，不需要改**，属于“教科书级”。

```
ALTER TABLE search_record
ADD COLUMN normalized_keyword VARCHAR(255)
GENERATED ALWAYS AS (
  LOWER(
    REGEXP_REPLACE(TRIM(keyword), '\\s+', ' ')
  )
) STORED;

CREATE INDEX idx_normalized_keyword
ON search_record (normalized_keyword);
```

> ✅ 后面 **所有逻辑只用 normalized_keyword**

------

# Step 2️⃣ ❌ 去掉 View，改为「完成态关键词表」

## 🎯 新目标

用一张表：

- 明确标记 **哪一次搜索是“完成态”**
- 保留原始搜索维度（user / ip / time）
- **可增量计算**
- **可回溯**

------

## Step 2.1 建表：final_search_keyword

```
CREATE TABLE final_search_keyword (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,

  search_record_id BIGINT NOT NULL,
  user_id BIGINT,
  ip VARCHAR(64),
  created_at DATETIME NOT NULL,

  normalized_keyword VARCHAR(255) NOT NULL,
  result_count INT,

  is_final_keyword TINYINT(1) NOT NULL,

  created_time DATETIME DEFAULT CURRENT_TIMESTAMP,

  UNIQUE KEY uk_search_record (search_record_id),
  KEY idx_final (is_final_keyword),
  KEY idx_keyword (normalized_keyword),
  KEY idx_user_time (user_id, created_at),
  KEY idx_ip_time (ip, created_at)
);
```

> 💡 设计点：
>
> - **search_record_id 唯一** → 可重复跑
> - **is_final_keyword 显式存储** → 不靠计算
> - user / ip 都保留 → 和你原逻辑完全一致

------

## Step 2.2 写入逻辑（核心 SQL）

### 👉 一次性跑（或定时增量）

```
INSERT INTO final_search_keyword (
  search_record_id,
  user_id,
  ip,
  created_at,
  normalized_keyword,
  result_count,
  is_final_keyword
)
SELECT
  sr.id,
  sr.user_id,
  sr.ip,
  sr.created_at,
  sr.normalized_keyword,
  sr.result_count,

  -- 是否完成态
  NOT EXISTS (
    SELECT 1
    FROM search_record sr2
    WHERE
      COALESCE(sr2.user_id, sr2.ip) = COALESCE(sr.user_id, sr.ip)
      AND sr2.created_at > sr.created_at
      AND sr2.created_at < sr.created_at + INTERVAL 10 SECOND
      AND sr2.normalized_keyword LIKE CONCAT(sr.normalized_keyword, '%')
      AND CHAR_LENGTH(sr2.normalized_keyword) > CHAR_LENGTH(sr.normalized_keyword)
  ) AS is_final_keyword

FROM search_record sr
LEFT JOIN final_search_keyword fsk
  ON fsk.search_record_id = sr.id
WHERE fsk.search_record_id IS NULL;
```

### ✅ 你现在能做到什么？

```
SELECT normalized_keyword, is_final_keyword
FROM final_search_keyword
WHERE ip = '99.235.83.157'
ORDER BY created_at;
```

👉 你会得到 **和原 View 一模一样的结果**，但这次是 **实体数据**。

# Step 3️⃣ ❌ 去掉 View，改为「产品关键词候选表」

## 🎯 新目标

这张表回答一个问题：

> **“哪些搜索词，值得当成产品 / 页面 / SEO 关键词？”**

------

## Step 3.1 建表：product_keyword_candidate

```
CREATE TABLE product_keyword_candidate (
  id BIGINT PRIMARY KEY AUTO_INCREMENT,

  product_keyword VARCHAR(255) NOT NULL,

  search_times INT NOT NULL,
  user_cnt INT NOT NULL,

  avg_results DECIMAL(10,2),
  zero_result_times INT,

  first_seen DATETIME,
  last_seen DATETIME,

  stat_date DATE NOT NULL,

  UNIQUE KEY uk_keyword_date (product_keyword, stat_date),
  KEY idx_search_times (search_times),
  KEY idx_user_cnt (user_cnt)
);
```

> 💡 `stat_date`
>
> - 允许你做 **按天 / 按周 / 按月趋势**
> - 非常关键（后面你一定会用）

------

## Step 3.2 聚合写入 SQL（每日跑）

```
INSERT INTO product_keyword_candidate (
  product_keyword,
  search_times,
  user_cnt,
  avg_results,
  zero_result_times,
  first_seen,
  last_seen,
  stat_date
)
SELECT
  normalized_keyword AS product_keyword,
  COUNT(*) AS search_times,
  COUNT(DISTINCT COALESCE(user_id, ip)) AS user_cnt,
  AVG(result_count) AS avg_results,
  SUM(result_count = 0) AS zero_result_times,
  MIN(created_at) AS first_seen,
  MAX(created_at) AS last_seen,
  CURDATE() AS stat_date
FROM final_search_keyword
WHERE
  is_final_keyword = 1
  AND CHAR_LENGTH(normalized_keyword) >= 5
GROUP BY normalized_keyword
ON DUPLICATE KEY UPDATE
  search_times = VALUES(search_times),
  user_cnt = VALUES(user_cnt),
  avg_results = VALUES(avg_results),
  zero_result_times = VALUES(zero_result_times),
  first_seen = LEAST(first_seen, VALUES(first_seen)),
  last_seen = GREATEST(last_seen, VALUES(last_seen));
```

------

## Step 3.3 你现在能直接做的事

### 🔥 找「值得做页面的词」

```
SELECT *
FROM product_keyword_candidate
WHERE
  user_cnt >= 10
  AND avg_results < 20
  AND zero_result_times < 3
ORDER BY search_times DESC
LIMIT 20;
```

### 🔥 找「强需求但无结果」

```
SELECT *
FROM product_keyword_candidate
WHERE
  zero_result_times >= 5
ORDER BY zero_result_times DESC;
```
