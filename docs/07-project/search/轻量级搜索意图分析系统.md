# 轻量级搜索意图分析系统

**Product Requirement Document（PRD）**

------

## 1. 产品背景（Why）

在多数业务系统中，搜索日志是**最被低估的数据资产**：

- 用户每天在搜索框里反复输入
- 这些输入**直接暴露真实需求**
- 但现实中：
  - 搜索日志只被用来排查问题
  - 或做简单 PV / UV 统计
  - **很少直接反哺产品决策**

### 核心问题

> **“用户到底想要什么？我下一步应该做什么产品？”**

现有方式的痛点：

- 依赖调研、拍脑袋
- 或重模型、重算法、周期长
- 分析结果难解释、难复用、难工程化

------

## 2. 产品目标（Goal）

### 🎯 一句话目标

> **用真实用户的搜索行为，在不依赖 NLP / 模型的前提下，
>  每天自动产出一份「可执行的产品开发建议清单」。**

### 具体目标

- 从搜索日志中识别 **用户真实完成态意图**
- 自动筛选 **值得做成产品 / 页面 / 功能的关键词**
- 给出 **明确、可落地的行动建议**
- 支持：
  - 每日自动运行
  - 可回溯
  - 可调规则
  - 可横向复用到不同业务

------

## 3. 产品定位（Positioning）

### 产品定位

> **一套“工程友好、完全可解释”的搜索意图分析系统**

### 明确不做的事（边界）

- ❌ 不做复杂 NLP
- ❌ 不做语义理解 / embedding
- ❌ 不做个性化推荐
- ❌ 不追求意图 100% 准确

### 我们要的不是“完美理解”，而是：

> **“足够可靠地指导产品下一步该做什么”**

------

## 4. 核心设计原则（Principles）

1. **轻量优先**
   - 只用 MySQL + 定时任务
   - 不引入外部依赖
2. **结果可解释**
   - 每一个结论都能追溯到原始搜索记录
3. **工程可落地**
   - 所有中间结果必须落表
   - 支持增量跑、重复跑
4. **以决策为终点**
   - 最终输出不是分析，而是行动建议

------

## 5. 核心用户 & 使用场景

### 目标用户

- 产品负责人 / 创始人
- 独立开发者
- 中小团队（无专职数据团队）

### 典型使用场景

- 决定**下一个产品主题**
- 决定**新增功能 / 页面**
- SEO / Landing Page 选题
- 判断“需求是真实存在，还是错觉”

------

## 6. 系统整体架构（逻辑层）

```
搜索日志
  ↓
关键词归一化
  ↓
完成态意图识别
  ↓
产品关键词聚合
  ↓
规则评分
  ↓
行动建议输出
```

### 核心思想

> **从“行为” → “意图” → “决策”**

------

## 7. 核心功能模块

### 7.1 搜索关键词归一化

**目的**：消除无意义差异，为后续分析打基础

- 去前后空格
- 合并多余空格
- 全部转小写

📌 输出：`normalized_keyword`

------

### 7.2 完成态搜索意图识别（核心能力）

#### 设计思路

用户在搜索时，往往是：

```
v → va → val → vale → valentine
```

真正的意图是 **最后一次输入**。

#### 判断规则（简化版）

- 同一用户 / IP
- 短时间窗口内（如 10 秒）
- 后一次搜索是前一次的前缀扩展

👉 则前一次不是完成态

#### 输出

- 每一条搜索记录
- 明确标记：`is_final_keyword = 0 / 1`

------

### 7.3 产品关键词候选池

**目标问题**：

> 哪些“完成态搜索词”，值得作为产品或页面关键词？

#### 聚合维度

- 搜索次数
- 独立用户数
- 平均结果数
- 零结果次数
- 首次 / 最近出现时间

📌 输出：`product_keyword_candidate`

------

### 7.4 关键词评分系统

#### 设计目标

- 不用模型
- 用固定公式
- 可随时调权重、重算历史

#### 示例评分逻辑

- 搜索多 → 加分
- 用户多 → 加分
- 零结果多 → 强需求信号
- 结果太多 → 降权（竞争激烈）

📌 输出：`product_keyword_score`

------

### 7.5 行动建议生成（最终产物）

#### 决策分级示例

| 分数区间 | 建议     |
| -------- | -------- |
| ≥ 30     | 立即做   |
| 20–29    | 高优先   |
| 10–19    | 观察     |
| < 10     | 暂不考虑 |

📌 输出：`product_action_suggestion`

------

## 8. 最终产品输出（对用户真正有价值的部分）

### 每天可直接查看的内容

- ✅ 今日「立即做」的产品关键词
- ✅ 高优先但尚未开发的需求
- ✅ 连续出现但无结果的强需求
- ✅ 可作为 SEO / Banner / 选题的词

### 产品形态

- 表（SQL）
- API
- 简单后台页面
- 或定时导出给产品 / 运营

------

## 9. 技术实现概览（Engineering）

### 技术栈

- MySQL
- 定时任务（Cron / Spring @Scheduled）

### 特点

- 0 外部依赖
- 全部 SQL 可读
- 支持按天趋势分析
- 适合长期运行

------

## 10. 可扩展方向（非当前范围）

> **明确：以下不是当前版本必须做的**

- 拼写纠错（Levenshtein）
- 同义词合并
- 趋势加权（连续 N 天上升）
- 关键词 → 功能级需求映射
- 与收入 / 转化率关联，做 ROI 预估

------

## 11. 产品价值总结

### 对产品

- 不再凭感觉选方向
- 需求来源清晰可解释

### 对研发

- 规则简单、稳定
- 无复杂依赖

### 对团队

- 搜索日志真正变成资产
- 决策开始“自动化”

------

## 12. 一句话产品价值（对外）

> **这是一个用最小技术复杂度，把用户搜索行为直接转化为产品决策的轻量级意图分析系统。**
