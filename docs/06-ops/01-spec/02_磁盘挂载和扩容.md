# 一、新建磁盘挂载

新创建 EC2 实例后，系统只有默认一个 8G 的硬盘，大部分场景下是不够用的，比如我们有搭建数据库的需求。这时候，我们通常申请一张盘，挂载到 `/data` 路径下。

##### 确认磁盘是否已挂载到 EC2（控制台）

在 **AWS 控制台 → EC2 → Volumes** 中确认：

- 状态：`in-use`
- Attached instance：你的 EC2
- Device：例如
  - `/dev/xvdf`
  - `/dev/nvme1n1`（**Nitro 实例常见**）
  - /dev/xvda for root volume. /dev/sd[f-p] for data volumes.

![image-20260111081610847](https://wristo-wiki.oss-cn-beijing.aliyuncs.com/wiki20260111081620757.png)

> ⚠️ AWS 控制台里的设备名 ≠ Linux 内真实名称（尤其是 NVMe）

##### 在 EC2 上确认磁盘设备名

```
lsblk
```

常见输出示例：

```
NAME        SIZE TYPE MOUNTPOINT
nvme0n1     50G  disk 
├─nvme0n1p1 50G  part /
nvme1n1    200G  disk
```

或传统块设备：

```
xvda   50G disk /
xvdf  200G disk
```

👉 **新盘通常是：**

- `nvme1n1`（NVMe）
- 或 `xvdf`

##### 三、（如果是新盘）创建文件系统 ⚠️只做一次

❗️**确认该盘没有数据**，否则会被清空

**查看是否已有文件系统**

```
sudo file -s /dev/nvme1n1
```

如果显示：

```
data
```

说明是新盘，可以格式化。

**格式化（推荐 ext4）**

```
sudo mkfs.ext4 /dev/nvme1n1
```

（如果是 xvdf）

```
sudo mkfs.ext4 /dev/xvdf
```

------

##### 四、创建挂载目录 `/data`

```
sudo mkdir -p /data
```

------

##### 五、临时挂载（立刻生效）

```
sudo mount /dev/nvme1n1 /data
```

或：

```
sudo mount /dev/xvdf /data
```

验证：

```
df -h
```

看到类似：

```
/dev/nvme1n1   200G  ...  /data
```



##### 六、设置开机自动挂载（⚠️非常重要）

**获取 UUID（强烈推荐用 UUID）**

```
sudo blkid
```

示例输出：

```
/dev/nvme1n1: UUID="a1b2c3d4-xxxx" TYPE="ext4"
```

 **编辑 `/etc/fstab`**

```
sudo vi /etc/fstab
```

追加一行：

```
UUID=你的volumeUUID  /data  ext4  defaults,nofail  0  2
```

**参数解释（推荐这样写）：**

- `defaults`：标准参数
- `nofail`：⚠️ 磁盘异常时 **不阻塞系统启动**
- `0 2`：fsck 顺序

**3️⃣ 验证 fstab 是否正确（很关键）**

```
sudo mount -a
```

**没有报错 = 安全**



# 二、重启后磁盘重新挂载



一般数据库目录 位于 /data 下，我们会使用单独的磁盘进行挂载。当服务器进行重启时，磁盘不会自动挂载，所以，重启后，我们应该手动对数据盘进行挂载。



## 手动挂载

使用 `lsblk` 和 `mount` 命令来检查和挂载磁盘。

```
lsblk
NAME      MAJ:MIN RM SIZE RO TYPE MOUNTPOINTS
xvda      202:0    0   8G  0 disk 
├─xvda1   202:1    0   8G  0 part /
├─xvda127 259:0    0   1M  0 part 
└─xvda128 259:1    0  10M  0 part /boot/efi
xvdb      202:16   0  10G  0 disk 


sudo mount /dev/xvdb /data
```

# 磁盘扩容

## AWS EC2 控制面板修改磁盘大小

- 从`AWS Console`进入 EC2选择要扩容的 Volume
- 选择需要扩容的磁盘，点击`操作`按钮
- 点击`修改`卷
- 卷类型选择`通用型SSD(gp2)`（可以根据自己的需求选择其他类型）
- 大小输入`16`（按需输入）
- 点击确认修改

## 检查磁盘是否真的扩容成功

```
lsblk
```

输出示例（看 `xvda` 与 `xvda1` 的 Size）：

```
NAME        MAJ:MIN RM  SIZE RO TYPE MOUNTPOINT
xvda        202:0    0   32G  0 disk 
└─xvda1     202:1    0   16G  0 part /
```

如果 `xvda` 显示为 32G、但 `xvda1` 还是 16G，说明磁盘已扩但分区没扩。

## 扩容分区

```
sudo growpart /dev/xvda 1
```

如果成功，你会看到提示类似：

```
CHANGED: partition=1 start=2048 old: size=33552384 end=33554432 new: size=41940991 end=41943039
```

## 验证

扩展文件系统后，使用 **df-h** 命令验证操作系统是否可以看到额外的空间：

```
df -h
```



## 如果文件系统还没有扩展

------

### ✅ 下一步：扩展文件系统

你只需要再执行一个命令，让文件系统识别扩容后的空间。

如果你使用的是 **`xfs` 文件系统**（大概率是，因为 Amazon Linux 2 默认是 xfs）：

```
sudo xfs_growfs /
```

如果你使用的是 **`ext4` 文件系统**：

```
sudo resize2fs /dev/xvda1
```

------

### ⚠️ 检查文件系统类型

你可以用以下命令确认使用的是哪种文件系统：

```
df -T /
```

输出类似：

```
Filesystem     Type  Size  Used Avail Use% Mounted on
/dev/xvda1     xfs    8G  7.8G  206M  98% /
```

### 🚀 执行完后再查：

```
df -h
```

# 扩容 `/data` 的方法

1. **确认文件系统类型**

   ```
   df -Th /data
   ```

   - 如果是 `ext4`：用 `resize2fs`
   - 如果是 `xfs`：用 `xfs_growfs`

2. **直接扩展文件系统**

   - ext4:

     ```
     sudo resize2fs /dev/xvdb
     ```

   - xfs:

     ```
     sudo xfs_growfs /data
     ```

3. **检查结果**

   ```
   df -h /data
   ```

------

💡 小结：
 你的 `/data` 是直接格式化到整个 `/dev/xvdb` 磁盘上的，所以不需要分区扩容，只要扩文件系统即可。
